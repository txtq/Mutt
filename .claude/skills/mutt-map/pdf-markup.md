# PDF markup

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- PDF markup (owner only, PDFs only): `pdfedit.js` + `pdfedit.css`, fetched by `viewer.js` the first time words are picked on a PDF or "Mark up" is pressed. Everything is written into the PDF with pdf-lib (`loadPdfLib` in `pdfjs.js`) and saved by `PUT /api/blocks/<id>/file` (raw bytes; PDFs only; `meta.rev` goes up and the file's address becomes `/f/<id>/r<rev>/<name>`, so nothing stale is shown). Marks are real annotations (Highlight, Underline, StrikeOut, Ink, FreeText, Text) with appearance streams, each carrying `/MuttData` (JSON) so Mutt reads its own back exactly; other apps' highlights, ink and notes are read and can be changed too. Changed words: a patch of the page's colour and the new words in the nearest standard face, as Mutt's own content streams listed on the page (`/MuttEdits`, `/MuttEditStreams`, fonts `/MuttF<n>`), taken out again when the file is next opened for markup, so a change stays changeable. While marking up, the page is drawn from a copy without Mutt's marks (`view.swap`) and the marks are drawn by Mutt over it. `changedLines`/`withChangedLines` swap covered words for the new ones when a PDF is read out.
