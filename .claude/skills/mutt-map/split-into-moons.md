# Split into moons

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- Split into moons (`drawers.modes.split` {dismissed; `last` = what the last split moved, kept for its Undo and never sent to the page, `shown_modes` in `mutt/api.py`}): a registry entry that acts once instead of showing the planet another way (`shows=False` in `mutt/modes.py`, so it can never be on; `act` in place of `load`/`view` in `modes.js`; `turnOn` in `views/planet.js` runs it). `mutt/split.py` reads each of the owner's files with the same sorter (`sorting.member`: topics, concepts, what a picture shows) and gathers the clear ones by subject (`subject`, `groups`: 3+ files and 15%+ each, together half the planet); `plan` keeps a group the planet is named after on the planet, sends a group to a moon of the same name if there is one, and makes new moons biggest first while there is room (`MAX_MOONS`), the rest staying. Its bars are the plain share rule on the second biggest group (on 25%, stay 15%, least 4). Other people's files (community planets) are never read or moved. Routes: `POST /api/drawers/<id>/split` (new moons start like `create_drawer`'s, `moon_start`; files keep their ticks) and `POST .../split/undo` (every file back in its old place; a made moon goes if nothing new was put on it). Page: `splitIntoMoons`/`undoSplit` in `views/planet.js`, `Collection.setBlocks` for the one glide. Checks: the foot of `tests/modes.sh`, browser path `split_moons`.
