# Autosort

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- Autosort likens a new file to each file on a planet, after Nosofsky's Generalized Context Model (2026-11-16, `sorting.py` "likeness to each file"): `apart` measures how far two files are along seven lines (words, subject, kind, form, look, moment, site), `attention` weighs them per planet (from what it reads as, times what it learned, `planet_attention`), `likeness` = exp(-c·d), and `alike_match` adds up the closest `NEAREST` per planet into the `alike` clue, a file placed by hand counting twice one autosort placed (`connections.placed`: 'hand' / 'auto', set by `connect`; empty = from before). When the owner takes a file off a planet autosort put it on (`remove_connection` → `learn_from_move` → `sorting.learn`), both planets learn which lines told them apart. `pick` returns (planet, None, other) or (None, new title, None): a new planet is the background that wins when nothing fits (`fits`), and on a close call (`pull` = odds of fitting, runner-up ≥ `CLOSE_CALL` of the winner's) `sortedInto.or` names the second planet, which the toast offers as "<planet> instead" (`sortedToast` in `actions.js`). Taking "writing" out of `GROUP_NAMES`' Notes was part of it: a planet called Writing is about writing, not for any note.
- Autosort (`mutt/sorting.py`, scores every planet on name, topics and concepts, files already there, kinds, sites, how notes are written and what the planet is for; words in `mutt/lexicon.py`), adding a file straight onto a planet (`drawer` in `POST /api/blocks` or `?drawer=` on upload) and link previews (`mutt/links.py`) are all server-side.
