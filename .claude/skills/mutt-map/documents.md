# Documents mode

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- Documents mode (`drawers.modes.documents`, offered by `documents.doc_signs` when a planet is mostly longer writing; the "Long for a note" hint appears at 1000 characters): a document is still a note. Its Markdown stays in `blocks.content`, and the editor's fuller HTML sits in `docs` (cleaned against an allowlist in `mutt/documents.py`; ignored if the note was edited since). Also `doc_versions`, `doc_images` and `doc_comments` (anchored by quote, prefix and suffix), with routes under `/api/docs/<id>`. Front end: `docs.js` (the desk of pages and the offer), `doceditor.js` (the editor; each document stands alone, with no list of the others beside it; an open document's address is `/p/<id>?doc=<blockId>`; the page flies between its card on the desk and the sheet (`arrive`/`depart`), the planet page fades away under `html.is-writing` leaving the sky; a slim toolbar with one Aa panel (`typePanel`), a formatting bubble beside selected words (`selectionBar`), `/` on an empty line to insert (`slashCheck`), smart punctuation (`smarten`), and quiet writing (`typing`/`wake`: the bars fade after steady typing)), opening a note as a document from its file view on its planet turns the planet into a desk with an Undo (`doc:desk` from `viewer.js`, taken by `views/planet.js`), `docformat.js` (Markdown↔HTML, the cleaner), `docexport.js` (PDF via pdf-lib, a hand-built .docx, Markdown, text, print) and `docs.css`.
  - Kinds of writing (`settings.layout`: auto, prose, poem, script, journal, letter; `documents.KINDS`): the first toolbar button ("Writing as") picks one, Auto reads it from the words (`docwriting.js` `readsAs`, the server's `documents.reads_as`; it takes clearer signs to switch than to stay, `stillReads`), and the rest of the toolbar follows the kind (`kindTools`). Poem: syllables, rhyme letters with the rhyming words underlined, every fifth line numbered (per device, `mutt:docs-poem`), the form's name in the word count. Script: lines are `p.sc-scene|action|char|paren|dial|trans`, Enter/Tab move between parts, names finished from the cast, scenes in the outline, typewriter type. Journal: `h2.dated` entries, "New entry"/"Today". Letter: date and sign-off. Lists are one button with six kinds (`ul`, `ul.dash`, `ol`, `ol.alpha`, `ol.roman`, `ul.check`). New classes must be added to both cleaners (`CLASSES` in `documents.py` and `docformat.js`); don't call one `entry` (mutt.css has a global `.entry`).
- Making a document from a file (`mutt/convert.py`): Word (.docx), OpenDocument (.odt) and RTF are read on the server into the editor's HTML (pictures into `doc_images`), text and Markdown as they are; a PDF is read in the browser (`pdfAsDocument` in `viewer.js`, with `pdfbook.js`) and its HTML posted. `GET /api/blocks/<id>/document` gives a Word/ODT/RTF file's pages for the file view (`docStage`); `POST` makes a new note + `docs` row placed just after the file (which is kept; `meta.madeFrom`), and the file view steps aside to it (`?doc=`). `tests/make_docs.py` makes the sample files for `tests/docs.sh`.
