# Live updates

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- Live updates (2026-11-16): every open page hears what changed elsewhere (someone else, or you on another device) without a reload. `mutt/live.py`: one Server-Sent Events stream per page (`GET /api/live?tab=`, a thread each; pings every 20 s; a page in the background lets it go after `--beat-rest`) and `POST /api/live/watch` {tab, planet | galaxy} (a planet only if `drawer_visible`). `app.dispatch` calls `live.before` / `live.after` round every change that went through: from the route's ids (block, drawer, beam) and the answer's `block` it works out the planets, galaxies and people touched and sends notices that carry only what to look at again (`planet` id, `galaxy`, `universe`, `beams`, `comments`, `keep`, `comets`), never what a file holds; the page sends `X-Mutt-Tab` (`TAB` in `api.js`) so it isn't told of its own changes. `QUIET` lists the routes that touch nothing anyone else sees. Front end: `live.js` (the stream, `watch()` called by the router with `inst.watch`; a reopened stream sends `again`), the router hands each notice to `inst.live`: a planet asks for itself again and emits only the differences as the usual `block:*` bus events (`syncPage` in `views/planet.js`; a mode turned on or off elsewhere builds the page again; `ticked` in `listmode.js`), the galaxy `heard` refreshes itself, its universe and comets; the comment notes, keep tip and comet notes ask again (`refresh`). Read-only collections now follow `block:*` too. Checks: the live block at the foot of `tests/together.sh`, browser path `live_updates`. One process holds the streams in memory, so Mutt must run as one process.
