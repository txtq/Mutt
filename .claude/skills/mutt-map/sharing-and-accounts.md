# Who sees what, names and getting back in

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- Who can see a planet: `drawer_visible`. A Code planet opens with its own code (`drawers.share_hash`, set at `PUT /api/drawers/<id>/code`, never the owner's sign-in code), checked by `auth.try_share_code` with its own lockout (`share_failures`); opened planets are kept per session in `drawer_unlocks`. A moon is visible only if its planet is too (`moons_of` lists a planet's moons). Queries that list planets need `parent_id IS NULL`. `galaxy_of` builds `/api/galaxy[/user]`, including the owner's stars and stats. `list_galaxies` builds `/api/galaxies` (the universe). Every user is in the universe; planets someone can't see at all (private, or People they're not on) come as `private_planet` stand-ins (no name or files) and show blurred. New planets start Public with "Others can add files" off, and carry `modes.shareTip` until their owner first opens them (the one-time sharing tip in `views/planet.js`).
- Names and getting back in, with no identity asked (2026-11-15): `users.display_name` is any words someone wants to be called (`PUT /api/me/name`; `name` comes with `user_json` and each galaxy in `/api/galaxies` (the universe seats people A to Z by it), `ownerName` on a planet, on a locked planet's answer and on someone else's file on a planet, `byName` on a comment, `names` in `/api/users` (people search finds and shows it) and in `/api/comments/new` (the notes under the clock); a person named on their own is written "Bob Ray (@bob)" (`personLabel` in `util.js`), the name alone in possessives and tight labels like the universe (`DESIGN.md` "Names"); the front end shows it in place of `@username` where a person is shown, never where one is typed or picked). A recovery key (16 characters, `auth.new_recovery_key`; only its hash in `users.recovery_hash`) is given at sign-up and after any new code set without the old one, and made anew from the account sheet (`POST /api/me/recovery-key`); `POST /api/auth/recover` takes it with a new code (misses count with wrong codes; the key is spent). A device that has signed in can set a new code without the old one (`POST /api/me/pin` with `forgot`, checked by `auth.known_device`). On the sign-in page, two misses offer "Can’t remember it?"; "Ask for a reset" saves a `reset_requests` row that whoever runs Mutt (`MUTT_ADMIN`, or a script carrying `MUTT_ADMIN_KEY` as `X-Mutt-Admin`) sees under `/api/admin/resets` and answers with a one-time link (`reset_links`, three days, `/login?reset=…`). Front end: `views/login.js` (the steps), On someone else's galaxy or planet the bar's name opens a sheet about them instead (`personBody` in `statusbar.js`, from `GET /api/users/<username>`: name, joined, planets open/with a code/private, their files you can see, planets kept together and files you saved from them). The account sheet (`settingsBody` in `statusbar.js`) keeps name and looks on its first page and the rest behind doors (`sheetPages`): Recently deleted, Your files, Code and recovery key (with Delete account). `account.js` (`showRecoveryKey`, `forgotPin`, `saveName`, `askForName`: a tip at the top right each time someone with no name goes out into the universe, run by `statusbar.js`; and `askForKey`: a tip on your own galaxy for an account with no key, run by `statusbar.js` beside the comment notes; Not now is kept per device in `mutt:key-asked:<username>`, asks once more after a week, then never), `resets.js` (fetched only for the admin: the sheet's section and the toast). The checks are at the foot of `tests/lockout.sh`.
