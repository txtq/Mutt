# Recently deleted, note history, download everything

Part of the map of how Mutt is built (`CLAUDE.md`, Architecture, lists every file). Keep it current when this feature changes.

- Recently deleted: deleting a file (`DELETE /api/blocks/<id>`) only sets it aside for a week: `blocks.deleted_at` is set, its connections are taken off and kept in `blocks.deleted_from` (planet, position, ticked), and its files stay on disk. A set-aside file is invisible everywhere (`own_block` / `readable_block` refuse it unless asked with `deleted=True`; stars, stats, search and the picture to-do lists skip it), except to its owner's `/f/` and `/t/`. `GET /api/deleted` lists them, `POST /api/blocks/<id>/restore` puts one back on every planet that still takes it (a star if none), `DELETE` on one already set aside, `DELETE /api/deleted`, or `?forever=1` erase for good. `start_purging()` (started by `server.py`) erases week-old ones every hour. Files left behind by a deleted planet go there too. Front end: `restoreBlock` in `actions.js` (the Undo after Delete) and `recentlyDeleted()` in `statusbar.js` (the account sheet's section). Any new query that lists a user's files without going through `connections` needs `deleted_at IS NULL`.
- Note history (any note, not only documents): one history with documents, in `doc_versions` (`html` empty for a plain note). `keep_before` in `mutt/api.py` keeps a note's words as they were, dated when they were written, whenever they change (`PATCH /api/blocks/<id>`, a recipe card's save); changes within ten minutes count as one, and the first change always keeps the original. `POST /api/docs/<id>/versions/<vid>/restore` puts a copy back after keeping now as "Before restoring". `versions` (how many earlier copies) comes with your own notes. Front end: `history.js` (fetched by `viewer.js` only for your own note with a copy: the side section, the copy on the stage marked against now with a word diff, Put this back); the file menu's `History` row (`blockItems` in `actions.js`, `takeHistoryWish`). The document editor's Version history shows the same copies.
- Download everything (`GET /api/me/export`, `mutt/export.py`; the account sheet's "Your files" row in `statusbar.js`): one zip of the owner's own files, as a folder `<username>'s galaxy` with a folder per planet named after it (moons inside their planet, a file on several planets in each), `Stars`, `On other people's planets`, `Recently deleted`, plus `Your data.json` (account, settings, planets, every file's details, comments, reading places and highlights, document versions) and `Read me.txt`. Packed into an unlinked temporary file in `DATA_DIR` and streamed. `?mark=` comes back as the `mutt-export` cookie when packing is done, so the button can stay busy until then. A new table that holds something about a person belongs in `Your data.json` too.
